# certsecure_certificate (Resource)

Submits a certificate signing request (CSR) to a CA and template through CertSecure, and returns the issued certificate and its chain. Changing `csr_pem`, or reaching the `early_renewal_hours` window, renews the certificate in place with the CSR from the configuration. Changing any other argument issues a new certificate. With `revoke_on_destroy`, destroying the resource revokes the certificate.

The certificate is issued by the CA behind CertSecure (for example Microsoft CA) using the given template.
`certificate_pem`, `chain_pem` and the parsed fields (`serial_number`, `not_before`, `not_after`) are set once the
certificate is issued. CertSecure processes requests asynchronously; the provider waits for issuance up to the
`create` timeout, for a renewal up to the `update` timeout, and for a revocation up to the `delete` timeout (all
default to 5 minutes).

## Example Usage

### Minimal CSR enrollment

```terraform
# Minimal CSR enrollment: the private key is generated by Terraform and never
# leaves it. CertSecure only receives the CSR.
resource "tls_private_key" "app" {
  algorithm = "RSA"
  rsa_bits  = 2048
}

resource "tls_cert_request" "app" {
  private_key_pem = tls_private_key.app.private_key_pem

  subject {
    common_name = "app.example.com"
  }
  dns_names = ["app.example.com"]
}

resource "certsecure_certificate" "app" {
  csr_pem  = tls_cert_request.app.cert_request_pem
  ca_name  = "Issuing-CA-01"
  template = "WebServer"
}
```

### Full CSR enrollment

```terraform
# Full CSR enrollment with renewal, revocation, SANs and metadata.
resource "tls_private_key" "app" {
  algorithm = "RSA"
  rsa_bits  = 2048
}

resource "tls_cert_request" "app" {
  private_key_pem = tls_private_key.app.private_key_pem

  subject {
    common_name = "app.example.com"
  }
  dns_names = ["app.example.com"]
}

resource "certsecure_certificate" "app" {
  csr_pem     = tls_cert_request.app.cert_request_pem
  ca_name     = "Issuing-CA-01"
  template    = "WebServer"
  owner_email = "app-team@example.com"
  tags        = ["terraform", "app"]
  notes       = "Managed by Terraform"

  # Renew in place, with the same CSR, when the certificate expires within 30 days.
  early_renewal_hours = 720

  # Revoke the certificate in CertSecure when the resource is destroyed or replaced.
  revoke_on_destroy = true

  # Optional: request additional SANs.
  subject_alternative_names {
    dns = ["www.example.com"]
    ip  = ["192.0.2.10"]
  }

  timeouts {
    create = "10m"
    update = "10m"
    delete = "10m"
  }

  # Issue a replacement before revoking the old certificate.
  lifecycle {
    create_before_destroy = true
  }
}

output "certificate_pem" {
  value = certsecure_certificate.app.certificate_pem
}

output "chain_pem" {
  value = certsecure_certificate.app.chain_pem
}

output "serial_number" {
  value = certsecure_certificate.app.serial_number
}
```

### Delivery to AWS Certificate Manager

```terraform
# Deliver the certificate with the destination's own provider, here AWS
# Certificate Manager. Renewals re-import into the same ACM certificate (ARN).
resource "tls_private_key" "web" {

  rsa_bits  = 2048
}

resource "tls_cert_request" "web" {
  private_key_pem = tls_private_key.web.private_key_pem

  subject {
    common_name = "web.example.com"
  }
  dns_names = ["web.example.com"]
}

resource "certsecure_certificate" "web" {
  csr_pem             = tls_cert_request.web.cert_request_pem
  ca_name             = "Issuing-CA-01"
  template            = "WebServer"
  early_renewal_hours = 720
}

resource "aws_acm_certificate" "web" {
  private_key       = tls_private_key.web.private_key_pem
  certificate_body  = certsecure_certificate.web.certificate_pem
  certificate_chain = certsecure_certificate.web.chain_pem
}
```

## Renewal

The certificate is renewed **in place**: the resource keeps its address and Terraform plans an update, not a
replacement. The provider renews through CertSecure with the CSR in the configuration. CertSecure never generates or
stores a private key. A renewal happens when:

- **`csr_pem` changes.** The new CSR can be for the same key (for example to add a SAN) or for a new key (key
  rotation). Whether the destination keeps its identity, for example the ARN of an imported `aws_acm_certificate`,
  is decided by the destination provider, not by this one.
- **The certificate expires within `early_renewal_hours`.** On the first plan inside the window, the provider
  renews with the same CSR, so the renewed certificate is for the same key.

After a renewal, `id`, `enrollment_id`, `task_id`, `certificate_pem`, `chain_pem`, `serial_number`, `not_before` and
`not_after` describe the new certificate. Resources that reference them update in the same apply. The previous
certificate is **not revoked**: it stays valid until it expires, because a destination may still be serving it.
CertSecure records the new certificate as a renewal of the old one and stops expiry alerts for the old one.

Renewals that need approval do not submit twice. If CertSecure requires approval, the apply fails with the task ID
and `pending_renewal_task_id` records it, while the previous certificate stays in state and in use. Approve or deny
the request in CertSecure, then run `apply` again: it resumes the same request. If the request was denied, the next
`apply` submits a new renewal. Changing `csr_pem` again while a renewal is pending is refused until that request is
approved or denied. The same applies when a renewal does not complete before the `update` timeout.

Things to know:

- **Renewal runs only when Terraform runs.** Nothing renews the certificate between runs, so run `plan`/`apply` on
  a schedule (for example nightly) with an `early_renewal_hours` window long enough to cover missed runs.
- **The owner is inherited.** CertSecure keeps the owner of the original certificate. `owner_email` is recorded as a
  watcher.
- **Permissions.** The CertSecure user of the API token needs the *Renew Inventory Certificates* permission (or must be
  the owner or a watcher of the certificate) and *View Enrollment Database*.
- **Only active and expired certificates can be renewed.** A revoked certificate cannot be renewed; use
  `terraform apply -replace` to issue a new one.
- **Other arguments still issue a new certificate.** Changing `ca_name`, `template`, `owner_email`, `tags`, `notes`,
  `subject_alternative_names` or `override_csr_sans` replaces the resource.

## Revocation on Destroy

By default, destroying the resource only removes the certificate from Terraform state and emits a warning: the
certificate stays valid in CertSecure. Set `revoke_on_destroy = true` to revoke it instead. The provider then submits
the revocation to CertSecure and waits, up to the `delete` timeout, until CertSecure reports the certificate as
revoked.

- **Apply the setting before destroying.** Destroy uses the value in state, so a configuration that sets
  `revoke_on_destroy = true` must be applied once before `terraform destroy` revokes the certificate. Changing the
  setting never renews or replaces the certificate.
- **A replacement revokes the old certificate.** Changing an argument that issues a new certificate (for example
  `template`) destroys the old one. By default Terraform destroys before it creates, so the old certificate would be
  revoked while destinations still use it. Add `create_before_destroy`, so the new certificate is issued and passed to
  the resources that use it before the old one is revoked:

  ```terraform
  resource "certsecure_certificate" "app" {
    # ...
    revoke_on_destroy = true

    lifecycle {
      create_before_destroy = true
    }
  }
  ```
- **Renewals never revoke.** After an in-place renewal the previous certificate stays valid until it expires.
- **Only active certificates are revoked.** A certificate that is already revoked, expired, or no longer in CertSecure
  is removed from state without a revocation. A request that is still pending or awaits approval cannot be revoked:
  destroy removes it from state with a warning; deny it in CertSecure. A renewal still pending
  (`pending_renewal_task_id`) is not cancelled.
- **Permissions.** The CertSecure user of the API token must be the owner of the certificate (the user that requested
  it), a department PKI admin for its CA, or a global admin, and needs *View Enrollment Database*.
- **Failures keep the resource.** If the revocation fails or does not complete before the `delete` timeout, destroy
  fails and the certificate stays in state. Running destroy again checks the certificate first and does not revoke it
  twice once an earlier revocation has completed.
- **No revocation reason.** CertSecure records the CA's default revocation reason.

## Approval and Resuming a New Certificate

If the template requires approval, creation fails with an error that includes the enrollment ID (eid) and task ID.
The request is saved in state with no certificate yet, and stays in CertSecure where it can be approved or denied.
The same happens when issuance does not complete before the `create` timeout, or the certificate cannot be
downloaded.

Terraform marks a resource whose creation failed as *tainted*, and the next `apply` replaces a tainted resource: it
would submit a new request. To resume the saved request instead, untaint it and apply again:

```shell
terraform untaint certsecure_certificate.app
terraform apply
```

The plan shows an in-place update. The apply waits, up to the `update` timeout, for the saved request and downloads
its certificate; it does not submit a new request. If the request still awaits approval, the apply fails again and
the next `apply` resumes it again, with no further untaint.

The resource is replaced, and a new request submitted, instead of resumed when:

- the request was denied or failed in CertSecure, or the certificate it returned is not for the CSR's key;
- `csr_pem` changed while the request was pending (the pending request is for the previous key).

Deny the old request in CertSecure if it is still awaiting approval. Destroying a resource that has no certificate yet
removes it from state with a warning and does not cancel the request.

## Important Notes

- **Errors identify the request.** When creation fails after the request was submitted, the error contains the
  enrollment ID (eid) and task ID so the request can be found, approved, denied or revoked in CertSecure. If the
  enrollment ID was not known yet, nothing is saved in state and the next `apply` submits a new request.
- **Protect your state.** A private key generated with the `tls_private_key` resource is stored in Terraform state
  in plain text. Store state in an encrypted, access-controlled backend, or generate the key and CSR outside
  Terraform and pass only the CSR.
- **Subject alternative names.** Whether the CA honors SANs requested in `subject_alternative_names` (instead of only
  those in the CSR) depends on the CA and template configuration.

## Schema

### Required

- `ca_name` (String) Name of the CA in CertSecure, as listed by the `certsecure_cas` data source.
- `csr_pem` (String) PEM-encoded PKCS#10 certificate signing request, for example `tls_cert_request.example.cert_request_pem`. Validated at plan time when known. Changing it renews the certificate in place with the new CSR, for the same key or a new one.
- `template` (String) Certificate template name, as listed in the `names` attribute of the `certsecure_templates` data source (for Microsoft CA this is the template name, e.g. `WebServer`, not the display name `Web Server`).

### Optional

- `early_renewal_hours` (Number) Renew the certificate in place when it expires within this many hours. The renewal happens on the first plan and apply inside the window, with the CSR from the configuration. Defaults to `0` (disabled).
- `notes` (String) Additional notes recorded with the request in CertSecure.
- `override_csr_sans` (Boolean) When `true`, the certificate gets only the SANs in `subject_alternative_names`, replacing those in the CSR. When `false` (the default), they are added to the CSR's SANs. Requires `subject_alternative_names`.
- `owner_email` (String) Email address of the certificate owner, recorded in CertSecure and used for notifications.
- `revoke_on_destroy` (Boolean) When `true`, destroying the resource revokes the certificate in CertSecure and waits until the revocation completes. Defaults to `false`: destroy only removes the certificate from Terraform state and it stays valid. Apply the value before destroying, like any deletion setting. A replacement (for example after changing `template`) also revokes the old certificate: set `lifecycle { create_before_destroy = true }` so the new certificate reaches its consumers before the old one is revoked.
- `subject_alternative_names` (Block, Optional) Subject alternative names to request in addition to (or, with `override_csr_sans`, instead of) those in the CSR. Whether the CA honors requested SANs depends on its template and policy settings. (see [below for nested schema](#nestedblock--subject_alternative_names))

- `chain_pem` (String) The issuing CA chain as concatenated PEM certificates, issuer first (the certificate's issuer, then its issuer, up to the root). Does not include the certificate itself.

- `status` (String) Enrollment status reported by CertSecure, e.g. `active`, `pending`, `requested` (awaiting approval), `denied`, `failed`, or `revoked`. Refreshed on every read.

## Import

Import is supported using the following syntax, where the ID is the CertSecure enrollment ID (eid):

```shell
# Import an existing certificate by its CertSecure enrollment ID (eid).
terraform import certsecure_certificate.app 1477
```

Import reads the certificate, chain, status, `ca_name` and `template` from CertSecure. The CSR, tags, notes, owner
email and requested SANs cannot be recovered, and `task_id` is not available.

After import, the first apply records `csr_pem` from the configuration. If the CSR is for the same key as the
imported certificate, nothing is issued. If it is for a different key, the certificate is renewed with it. To keep
a configuration that sets `tags`, `notes`, `owner_email` or `subject_alternative_names` from replacing the imported
certificate, ignore those arguments:

```terraform
resource "certsecure_certificate" "app" {
  csr_pem  = tls_cert_request.app.cert_request_pem
  ca_name  = "Issuing-CA-01"
  template = "WebServer"
  tags     = ["terraform"]

  lifecycle {
    ignore_changes = [tags]
  }
}
```
